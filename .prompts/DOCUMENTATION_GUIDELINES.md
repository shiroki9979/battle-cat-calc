# 文件撰寫原則 (Documentation Guidelines)

1. **核心哲學 (Docs-as-Code)**: 
   - 文件應隨程式碼同步更新。
   - 使用 Markdown 格式儲存，並納入版本控制。
2. **撰寫重點**: 
   - 專注於解釋「意圖（Why）」與「決策背景」，而非單純重複程式碼邏輯。
   - 對於複雜架構，應包含架構決策紀錄 (ADR)。
3. **結構化內容**: 
   - 使用清晰的 H1, H2, H3 標題層級。
   - 對於複雜流程，優先使用 **Mermaid.js** 語法繪製流程圖。
4. **API 文檔要素**: 
   - 簡短描述功能。
   - 列出參數（型別、必填項、預設值）。
   - 列出回傳值與可能的錯誤代碼。
   - 提供一個可運行的範例程式碼。
5. **語氣規範**: 使用專業、客觀且主動的語氣。
