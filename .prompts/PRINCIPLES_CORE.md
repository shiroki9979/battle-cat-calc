# 核心開發設計原則

在撰寫程式碼時，請務必遵循以下原則：

1. **DRY (Don't Repeat Yourself)**: 避免重複的邏輯。如果一段邏輯出現兩次以上，請考慮抽象化或封裝。
2. **KISS (Keep It Simple, Stupid)**: 優先選擇簡單、直觀的解決方案。避免過度工程（Over-engineering）。
3. **YAGNI (You Ain't Gonna Need It)**: 只實作當前需求的功能，不要為了「未來可能」的需求預留複雜的架構。
4. **SOLID 原則**:
   - **SRP (單一職責)**: 每個類別/函式只負責一件事情。
   - **OCP (開閉原則)**: 對擴充開放，對修改封閉。
   - **LSP (里氏替換)**: 子類別必須能替換掉父類別而不影響程式正確性。
   - **ISP (介面隔離)**: 不應強迫客戶端依賴它們不使用的方法。
   - **DIP (依賴倒置)**: 高層模組不應依賴低層模組，兩者都應依賴抽象。
5. **少即是多**: 程式碼的價值在於它解決的問題，而非程式碼的行數。優先撰寫可讀性高且精簡的程式碼。
