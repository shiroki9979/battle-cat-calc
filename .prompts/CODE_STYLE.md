# 程式碼品質與風格指南

1. **命名規範**:
   - 變數與函式命名應具備描述性（Descriptive names），避免 `a`, `b`, `temp` 等無意義名稱。
   - 遵循語言慣例（如 Python 使用 snake_case, TypeScript 使用 camelCase）。
   - 布林值變數應以 `is`, `has`, `can`, `should` 開頭。
2. **函式設計**:
   - 函式長度應保持簡短（建議不超過 20 行）。
   - 參數數量應控制在 3 個以內，過多時請改用物件/結構體傳遞。
3. **註解規範**:
   - 不要註解「這段程式碼在做什麼」，而要註解「為什麼要這樣做」。
   - 程式碼應儘量自明（Self-documenting），避免冗餘註解。
4. **錯誤處理**:
   - 嚴禁靜默失敗（Silent Fail），應適當拋出異常或回傳錯誤狀態。
   - 優先處理邊界條件（Edge cases）與異常狀況（Early Return 模式）。
